## 纯文本复制出来的骨架

从浏览器里框选整个讨论页、复制到纯文本编辑器，得到的是这样一串：

```text
<主题标题>
#1 - 2025-9-15 20:15
...
Kflho
<正文，段落前保留两个空格>
6
4
1
1
  36 回复
  收集
  贴贴
顺序
#2 - 2025-9-15 20:20
 
 
...
Letheward
<正文>
21
1
#3 - 2025-9-15 20:26
...
金刚可怜 (无可救药的百合豚)
<正文>
#3-1 - 2025-9-15 20:32
回复
 
 
...
Kflho
<正文>
5
#4 - ...
```

固定成分：

| 成分 | 形态 | 处理 |
| --- | --- | --- |
| 主题标题 | 第一行，单独一行 | 复制品开头时去掉（笔记标题就是它）；出现在正文中间时保留 |
| 楼层头 | `#<主楼层>[-<子楼层>] - YYYY-M-D HH:MM` | 去掉；需要保留时由设置单独打开 |
| 折叠标记 | `...` 独占一行（有时前面是空格行） | 去掉 |
| 子回复控制 | `回复` 独占一行 | 去掉 |
| 用户名行 | `用户名` 或 `用户名 (签名)` | 转成 `**用户名**(签名)`，有主页地址时带链接 |
| 正文 | 原样（段首两个空格、`(bgm38)` 这类表情文本、引用行） | 保留；引用行保持 `某人 说: …` 原样 |
| 贴贴计数 | 正文之后 1–4 行纯数字 | 默认去掉（开关） |
| 页面控件 | `N 回复`、`收集`、`贴贴`、`顺序` | 去掉 |
| 子回复 | `#N-M` 独立成块，顺序跟在父楼层后面 | 与主楼层同样输出，不额外缩进 |

## 网页 DOM 里的对应物

页面结构和上面那份纯文本不是一一对应的，抓网页时直接读 DOM：

- 主楼层：`div.postTopic` / `div#post_<id>`
- 回复：`div.row_reply`
- 子回复：`div.sub_reply_bg`（嵌在父回复的 `div.topic_sub_reply` 里）
- 楼层与时间：`small` 里的 `a.floor-anchor`（`#3-1`）+ ` - 2025-9-15 20:32`
- 用户名：`strong a.l`（`href="/user/<slug>"`）
- 签名：`span.sign`（文本自带两侧圆括号）
- 正文：主楼 `div.topic_content`、回复 `div.reply_content .message`、子回复 `div.cmt_sub_content`
- 引用：正文里的 `div.quote > q`，内容是 `**某人** 说: …`
- 表情：`img.smile`，`alt="(bgm38)"`、`src="/img/smiles/tv/15.gif"`（相对路径）
- 贴贴：`div.likes_grid` 在 HTML 里是空的，计数由页面脚本
  `data_likes_list` 渲染。**抓网页时整块跳过**，不需要识别数字。

## 为什么贴贴计数不能靠"删数字"硬来

纯文本里计数就是 1–4 行孤立数字，和正文里的数字行（列表编号、楼层引用）长得一样。
当前判据：**只剥块尾的连续纯数字行**（最多 8 行），并且只在这个开关打开时剥；
正文中间的数字行不动。代价是"整条回复正文恰好只有数字"会被当成计数剥掉——
这种回复没有讨论价值，接受这个取舍（`structure.bangumi-log` 的备注里记了）。
